# 数据活动

这是一个完全静态的 GitHub Pages 页面，用于手动发起一次可控的网络数据活动。

## 当前版本功能

- 费用下拉选项：`£0.01`、`£0.02`、`£0.03`，默认 `£0.01`。
- 每次目标字节数都在所选金额的 `±20%` 范围内随机生成，不能关闭随机化。
- 页面每次打开或刷新时，都会从仓库根目录的 `url.txt` 读取默认 URL，一行一个。
- 页面中的 URL 可以临时增加、删除、清空或检测，但不会写回仓库；刷新后会重新加载 `url.txt`。
- 有 URL 时随机选择 3–5 个 URL 访问，然后用本仓库的 `payload.txt` 补齐剩余字节。
- URL 输入框为空时，完全使用本仓库的 `payload.txt`，不会访问任何自定义 URL。
- 直接打开页面时，会读取 Navigation Timing，将初始页面和 `url.txt` 的加载量尽量从本次目标预算中扣除。
- 最近 20 次使用记录保存在浏览器本地；URL 列表不再保存在浏览器本地。
- URL 检测使用真实的 CORS `GET` 请求，显示 HTTP 状态、可打开性、CORS、正文大小和失败原因。
- 点击“检测并清理 URL 线路”后，每条线路最多等待 `5 秒`；只保留 2xx、CORS 可读、最终地址为 HTTPS、正文非空且不超过 `5120 B` 的 URL，其余会从当前页面列表中移除。

## 默认 URL 配置

默认线路保存在仓库根目录的 `url.txt` 中，每行一个 URL。当前默认列表共 `100` 条，其中包含原有 10 条和新增 90 条。永久调整默认线路时，请直接编辑并提交该文件。

页面加载 `url.txt` 时会使用 `cache: no-store` 并附加时间戳参数，以尽量避免浏览器和 CDN 返回旧缓存。GitHub Pages 刚完成提交后仍可能需要短暂时间部署，页面会读取已经部署的最新版本。

网页输入框只是临时工作区：手动修改、清空或线路检测都不会改变 `url.txt`。重新打开或刷新页面后，会再次读取仓库配置。

## 金额与字节校准

当前按照既有测试结果校准：`128,684 B` 作为 `£0.03` 的经验基准，因此采用以下字节预算：

| 名义金额 | 基准字节数 | ±20% 目标范围 |
|---|---:|---:|
| £0.01 | 42,895 B | 34,316–51,474 B |
| £0.02 | 85,790 B | 68,632–102,948 B |
| £0.03 | 128,684 B | 102,947–154,421 B |

目标总量包含页面初始加载量。程序会另外预留约 4 KB 用于无法从浏览器精确读取的协议开销，因此网页显示的字节数是预算估计，不是账单承诺。
最终扣费以官方账单为准。官方也提示，请确认使用方式符合当前服务条款。

## URL 输入规则

最简单的格式是一行一个 URL：

```text
https://example.com/static/probe.txt
https://example.org/1kb.bin
```

目标站点必须允许当前 GitHub Pages 来源读取响应。没有 CORS 时，浏览器无法读取响应正文和真实大小，因此检测会自动移除该 URL。
检测会实际读取正文，按照 `5120 B`（5 KiB）上限判断；`Content-Length` 仅用于提前淘汰，最终仍以实际可读取正文为准。
旧版本中的 `URL|预计字节数` 写法仍可被识别，但只有通过真实 CORS 和实际大小检测后才会保留，检测后会自动去掉估算标记。
输入 URL 时不要填写账号、密码或私密链接。线路检测建议在 Wi‑Fi 下进行，每条 URL 最多等待 5 秒、最多读取约 5 KiB，实际网络开销还包括响应头、TLS 和其他协议开销。

## 推荐使用流程

1. 在仓库的 `url.txt` 中维护需要长期使用的默认线路。
2. 打开页面并等待默认线路加载完成。
3. 选择本次目标金额；需要时可临时编辑或检测当前 URL 列表。
4. 点击“开始测试”，等待页面显示完成。
5. 完成后按需关闭数据连接。

页面初始 HTML、`url.txt`、DNS、TLS、HTTP 头以及网络服务商的计费方式都可能影响最终扣费。请把网页显示的金额当作预算，不要当作账单承诺。
